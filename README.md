# Dashboard

Веб-панель мониторинга системы накопления энергии (аккумуляторная батарея
и связанное оборудование) с данными по интерфейсу CAN. Сделана на
[NiceGUI](https://nicegui.io/).

## Что показывает панель

- состояние накопителя энергии (НЭ): предупреждения, ошибки, число полных циклов заряда;
- статус силового преобразователя (БУП): напряжения и токи входа/выхода, режим работы, активные ошибки, состояние контактора;
- прокручиваемую таблицу устройств шины (СКИ, КК, БУП, ПУСК, СО) с состоянием, CAN ID, числом ошибок и временем отклика линии связи;
- заряд (SoC) и износ (SoH) батареи, запасённую энергию;
- напряжение, ток и температуру;
- состояние силовых контакторов;
- параметры охлаждения (обороты вентиляторов, положение заслонок);
- карту ячеек: напряжения и температуры каждой ячейки сеткой цветных плиток;
- журнал событий: изменения состояний НЭ и устройств, введённые команды;
- командную строку оператора (под журналом).

Оформление — в стиле [btop](https://github.com/aristocratos/btop): тёмная
тема, моноширинный шрифт, секторы в тонких рамках с подписью в верхней
линии, шкалы из блоков с цветом по порогам.

Сама панель не читает и не разбирает CAN-шину — значения параметров ей
подаёт извне другая программа (реальный источник или симулятор), через
словарь `PARAMETERS`. Пока такого источника нет, все значения — `"No data"`.

`PARAMETERS` разложен по устройствам, которые эти значения отправляют, по
карте `can_map.xlsx` (шина 1): `imd` (СКИ), `cc` (КК), `bup` (БУП), `pusk`
(ПУСК), `so` (СО) и `bune` (БУНЭ — его команды устройствам и внутренние
значения: SoC, SoH, энергия, U/I/T, контакторы). Имена устройств и
параметров совпадают с `canmap.yaml`, так что результат
`protocol.decode()` кладётся в `PARAMETERS[устройство]` без перевода.

## Структура проекта

```
app/
  app.py            — точка входа: запускает NiceGUI и собирает страницу
  protocol.py       — разбор кадров CAN-шины по описанию из canmap.yaml
  simulator.py      — имитация работающей системы для режима --debug
  frontend/
    layout.py       — загрузка pattern.yaml, построение CSS-сетки
    cells.py        — отображение содержимого ячеек панели
    command_line.py — виджет командной строки
    events.py       — журнал событий: следит за изменениями в PARAMETERS, принимает команды
    colors.py       — палитра, цвета рамок и индикации по состоянию/значению
    parameters.py   — текущие значения PARAMETERS по устройствам и список устройств DEVICES
    config.py       — пороги и константы (SoC, SoH, напряжение, ток, температура, шкалы, журнал)
    styles.py       — глобальные стили (CSS)
pattern.yaml         — раскладка панели: сетка, области, виджеты, заголовки и цвета рамок
canmap.yaml           — карта CAN-кадров (какие байты что значат)
can_map.xlsx          — та же карта в виде таблицы
vcan/                 — симулятор CAN-шины для тестов без реального оборудования
requirements.txt
```

Раскладка ячеек (сколько строк/столбцов, где что стоит, заголовки)
задаётся декларативно в `pattern.yaml`: у каждой ячейки есть `widget`
(что рисовать, см. `CELL_RENDERERS` в `app/frontend/cells.py`), `title`
(подпись в рамке) и `color` (цвет рамки из `BOX_COLORS` в
`app/frontend/colors.py`). Строки и столбцы сетки задаются долями (`1`,
`2.6`) или CSS-размерами (`auto`).

## Запуск

```
pip install -r requirements.txt
python app/app.py
```

Режим отладки — все параметры имитируют работу системы:

```
python app/app.py --debug
```

Преобразователь по кругу проходит режимы (предзаряд, ожидание, заряд,
разряд). За ним меняются SoC, напряжения, токи, напряжения и температуры
ячеек, обороты вентиляторов и шиберы, контакторы. Изредка возникают и сами
проходят неисправности: низкая изоляция, перенапряжение БУП, потеря датчика
температуры. В рамке сектора can в этом режиме горит метка `simulation`.

Все секторы панели обновляются на лету (каждые 0,5 с) из `PARAMETERS`.

Дальше NiceGUI поднимет веб-сервер и покажет адрес в консоли (по
умолчанию `http://localhost:8080`) — открывайте его в браузере.

Для теста без настоящей CAN-шины можно поднять виртуальный интерфейс и
погонять по нему случайные кадры через `vcan/vcan.py` (линукс-only,
использует `vcan`/`socketcan`).

## Требования

- Python 3.10+
- зависимости из `requirements.txt` (NiceGUI, PyYAML, python-can)
- браузер с поддержкой HTML5/CSS3/JS
