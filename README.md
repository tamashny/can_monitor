# CAN monitor

Веб-панель мониторинга накопителя энергии (НЭ) и его устройств по шине CAN.
Читает кадры с USB-CAN адаптера SLCAN через COM-порт, разбирает их по карте
`config/canmap.yaml` и показывает в браузере. Сделана на
[NiceGUI](https://nicegui.io/), оформление — в стиле
[btop](https://github.com/aristocratos/btop).

## Что показывает панель

- источник данных: адаптер (порт, скорость, подключён ли, кадров в секунду) или имитация;
- состояние НЭ: предупреждения, ошибки, число полных циклов заряда;
- прокручиваемую таблицу устройств шины (СКИ, КК, БУП, ПУСК, СО): состояние, CAN ID, число ошибок, время с последнего кадра;
- заряд (SoC) и износ (SoH), запасённую энергию;
- напряжение, ток и температуру накопителя;
- преобразователь (БУП): режим, напряжения и токи входа/выхода, активные ошибки, контактор;
- силовые контакторы и систему охлаждения (обороты вентиляторов, шиберы);
- карту ячеек: напряжения и температуры каждой ячейки сеткой цветных плиток;
- журнал событий (изменения состояний, подключение адаптера, введённые команды и их результат) и командную строку под ним.

Все значения обновляются на лету.

## Запуск

```
pip install -r requirements.txt
python app/main.py
```

Панель откроется по адресу `http://localhost:8080`.

| Команда                            | Что делает                                                 |
|------------------------------------|------------------------------------------------------------|
| `python app/main.py`               | читает шину с адаптера, порт из `config/settings.yaml`     |
| `python app/main.py --port COM5`   | то же, но с другим COM-портом                              |
| `python app/main.py --debug`       | без адаптера: все параметры имитируют работу системы       |

Если порт не открывается (адаптер не подключён, порт занят), в секторе can
горит `disconnected`, причина пишется в журнал, а подключение повторяется
каждые несколько секунд. Как только адаптер появится, данные пойдут сами.

### Режим отладки (`--debug`)

Преобразователь по кругу проходит режимы (предзаряд, ожидание, заряд,
разряд). За ним меняются SoC, напряжения, токи, напряжения и температуры
ячеек, обороты вентиляторов и шиберы, контакторы. Изредка возникают и сами
проходят неисправности: низкая изоляция, перенапряжение БУП, потеря датчика
температуры. В рамке сектора can горит метка `simulation`.

## Настройки

Всё, что может понадобиться поменять, лежит в `config/`. Изменения
применяются после перезапуска панели.

| Файл                   | Что в нём                                                                 |
|------------------------|---------------------------------------------------------------------------|
| `config/settings.yaml` | COM-порт и скорости адаптера, порт веб-страницы, пороги цветов, таймауты связи устройств, размеры карты ячеек, журнал |
| `config/canmap.yaml`   | карта CAN-кадров: какой байт какой параметр, масштаб, значения кодов       |
| `config/pattern.yaml`  | раскладка панели: сетка, какой сектор где, заголовки и цвета рамок         |
| `config/commands.yaml` | команды оператора для командной строки (пока пусто, формат описан в файле) |

### Команды

Встроенные команды панели (кадров в шину не шлют):

| Команда                       | Что делает                                                          |
|-------------------------------|---------------------------------------------------------------------|
| `/ports`                      | список активных COM-портов в журнале                                |
| `/connect COM5 500000`        | подключить адаптер к порту со скоростью CAN-шины (можно `500k`; без скорости — текущая) |
| `/disconnect`                 | отключить адаптер                                                   |

При открытии командной строки для каждого найденного COM-порта сразу
предлагается готовая строка `/connect <порт> <скорость>`. Допустимые
скорости SLCAN: 10k, 20k, 50k, 83.3k, 100k, 125k, 250k, 500k, 750k, 1000k.
В режиме `--debug` адаптера нет, и `/connect` не работает.

Кроме них командная строка предлагает команды из `config/commands.yaml`. У каждой
команды есть имя (то, что вводится в строке), описание, CAN ID кадра и
значения его параметров; раскладка байтов этого кадра описывается в
`config/canmap.yaml`, как и у принимаемых кадров. Сейчас команд нет, а
отправка кадров ещё не реализована: введённый текст попадает в журнал с
пометкой `unknown command` (или `sending is not implemented yet` для
описанной команды).

Исходная карта кадров в виде таблицы — `docs/can_map.xlsx`.

```
  canmap.yaml
  pattern.yaml
  commands.yaml

  can_map.xlsx             карта CAN-кадров в виде таблицы
app/
  main.py                  точка входа: флаги --debug / --port, сборка страницы
  settings.py              читает config/settings.yaml, пути проекта
  parameters.py            текущие значения PARAMETERS по устройствам, список DEVICES
  summary.py               состояния устройств и НЭ для таблицы systems
  canbus/                  CAN-шина
    protocol.py            разбор кадров по canmap.yaml
    reader.py              чтение с адаптера SLCAN в фоновом потоке
    commands.py            команды оператора из commands.yaml
  simulation/              режим --debug
    simulator.py           имитация работающей системы
  frontend/                веб-интерфейс
    cells.py               виджеты секторов и их обновление
    command_line.py        командная строка (поле ввода и список команд)
    events.py              журнал событий
    layout.py              сетка из pattern.yaml
    colors.py              палитра и цвета по порогам
    helpers.py             форматирование значений
    styles.py              CSS

  can_sender.py            отправка кадров имитатора через адаптер SLCAN
  vcan.py                  генератор случайных кадров на vcan (Linux)

```

### Как данные попадают на панель

`PARAMETERS` (`app/parameters.py`) разложен по устройствам, которые эти
значения отправляют, по карте шины 1: `imd` (СКИ), `cc` (КК), `bup` (БУП),
`pusk` (ПУСК), `so` (СО), `bune` (БУНЭ — команды устройствам и внутренние
значения). Отдельно `bus` — состояние адаптера.

`canbus/reader.py` получает кадр, `protocol.decode()` разбирает его по
`canmap.yaml`, и значения кладутся в `PARAMETERS[устройство]` под теми же
именами. Кадры ячеек 0x297 раскладываются по массивам `cell_voltages` и
`cell_temperatures` (номер кадра с 1, по 7 ячеек). По времени последнего
кадра считается связь с устройством, `summary.py` выводит из значений
состояния устройств и НЭ. Имитатор пишет в те же `PARAMETERS`, поэтому
панель не знает, откуда пришли данные.

## Отправка тестовых кадров через адаптер

```
python tools/can_sender.py --port COM7 [--bitrate 500000] [--verbose]
```

Шлёт в шину через адаптер SLCAN все кадры `canmap.yaml` с их периодами и
по кругу кадры ячеек 0x297. Значения берутся из имитатора (`app/simulation`),
кадры собираются функцией `protocol.encode()` — обратной к разбору. Так
проверяется вся цепочка: адаптер → шина CAN → второй адаптер (или BUNEcan)
→ дашборд на его порту (`python app/main.py --port COM6`).

## Тест без адаптера на Linux

```
python tools/vcan.py
```

Поднимает виртуальный интерфейс `vcan0` и шлёт по нему случайные кадры
из `canmap.yaml`. Чтобы панель читала его, в `config/settings.yaml`
поставьте `interface: socketcan` и `port: vcan0`.

## Требования

- Python 3.10+
- зависимости из `requirements.txt` (NiceGUI, python-can, pyserial, PyYAML)
- USB-CAN адаптер с протоколом SLCAN (CANable, USBtin, Lawicel и т. п.)
